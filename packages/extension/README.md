# A.I.M. Browser Bridge (`@aim/extension`)

Manifest V3 extension for Microsoft Edge and Google Chrome. It lets the A.I.M. desktop app drive
the browser in background tabs: open and navigate tabs, snapshot pages, click, type, select, read,
scroll, wait, evaluate, take screenshots, and show A.I.M.'s teal cursor inside the page. The payment
guard from `@aim/shared` runs inside the page before every click or keystroke, so purchases are never
completed.

The extension is a WebSocket **client**; the A.I.M. app ("Hub") is the server at
`ws://127.0.0.1:<port>/aim/ext` (default port 47821). It never talks to any other host.

## Build

```sh
pnpm --filter @aim/shared build        # once; the extension bundles @aim/shared
pnpm --filter @aim/extension build     # -> packages/extension/dist (self-contained)
node build.mjs --watch                 # rebuild on change (from packages/extension)
```

`dist/` is the folder to load. (The package folder itself also loads, because its `manifest.json`
points at `dist/...`.) Icons are generated by `node icons/generate-icons.mjs` and committed.

Checks: `pnpm --filter @aim/extension typecheck`, `pnpm --filter @aim/extension test` (unit tests,
no browser) and `node test/e2e.mjs` (headless Chromium + fake hub, see below).

## Install

### Microsoft Edge
1. Open `edge://extensions`.
2. Turn on **Developer mode** (bottom-left toggle).
3. Click **Load unpacked** and select `packages/extension/dist`.
4. Pin "A.I.M. Browser Bridge" from the toolbar's Extensions menu so the icon is visible.

### Google Chrome
1. Open `chrome://extensions`.
2. Turn on **Developer mode** (top-right toggle).
3. Click **Load unpacked** and select `packages/extension/dist`.

The extension reloads automatically when `dist/` changes only if you press the reload icon on the
extensions page; do that after every rebuild.

## Pairing with A.I.M.

1. In A.I.M., open **Settings** and copy the **Browser extension token** (and note the port if it
   is not the default 47821).
2. Click the A.I.M. Browser Bridge icon in the browser toolbar.
3. Paste the token into **Pairing token**, check the **Hub port**, and click **Save and connect**.
4. The status pill turns teal and reads **Connected to A.I.M.** The **Test connection** button
   performs a round trip and reports the result.

The token is stored only in the extension's local storage on this computer. If the token in A.I.M.
changes, paste the new one; the extension reconnects immediately.

## What the popup shows
- Connection status and, when disconnected, the reason (A.I.M. not running, wrong token, wrong port).
- Browser name and version, extension version.
- The number of tabs opened by A.I.M. in this browser session and a button to close them all.

## Troubleshooting

**Status says "A.I.M. is not reachable".** The A.I.M. desktop app is not running, or it listens on a
different port. Start A.I.M., compare the port in A.I.M. Settings with the popup, and press
**Save and connect**.

**Status says "Pairing token rejected".** The token in the popup does not match A.I.M.'s. Copy it
again from A.I.M. Settings (tokens change when A.I.M. regenerates them).

**The service worker went to sleep.** MV3 workers are suspended after about 30 s of inactivity.
The extension keeps the link alive with a ping every 20 s while connected and uses a 30 s alarm to
reconnect after a suspension or a browser restart. If the popup shows "Connecting…" for more than a
few seconds, open `edge://extensions` (or `chrome://extensions`), find the extension, and click
**Service worker** to inspect the console, or press **Reload**.

**Port busy.** If another program occupies 47821, change the port in A.I.M. Settings; A.I.M. shows
the port it actually bound. Enter the same number in the popup.

**Firewall or security software.** The connection is a plain WebSocket to `127.0.0.1` (loopback).
Some endpoint-security tools block loopback WebSockets from browsers; allow the browser to connect
to `127.0.0.1:47821` (TCP).

**A page cannot be automated.** Browser-internal pages (`edge://`, `chrome://`), the extension
stores, and `file:` URLs are off limits to extensions by design. A.I.M. receives a clear error.

**A click or keystroke was refused with "Blocked by A.I.M. policy".** The payment guard fired: the
element looks like a pay/checkout action, a card field, or the page is a checkout page. This is
intentional and cannot be disabled; A.I.M. hands over to you at that point.

**Screenshots fail for background tabs.** Browsers only capture the active tab of a window. A.I.M.
normally works from the DOM snapshot instead; it activates the tab first if a screenshot is required.

## Privacy

- The extension connects only to `127.0.0.1` (your own computer) and only when a pairing token has
  been entered. No data is sent anywhere else.
- Page content is read only when A.I.M. asks for it through the local connection.
- Password fields are masked in snapshots.
- Tab focus/blur events (URL and title only) are reported to A.I.M. for its behaviour summary; A.I.M.
  stores them locally.
- A.I.M.'s teal cursor is drawn inside a page only while that tab is visible, so you can always see
  when A.I.M. is acting in the tab you are looking at.

## End-to-end test

`node test/e2e.mjs` builds nothing; run `pnpm --filter @aim/extension build` first. It starts a fake
hub on `127.0.0.1:47821` (or a random port if busy), serves `test/fixtures/*.html`, loads `dist/` into
a headless Chromium via Playwright (`playwright` must be resolvable from the repo root or a global
install; set `AIM_E2E_BROWSER` to a Chrome binary), seeds the port and token through the service
worker, and runs the whole protocol: pairing (including a rejected token), tab management, snapshot,
payment-guard refusals ("Pay now", `cc-number`, card numbers), typing/submitting, selects, keys,
scrolling, reading, waiting, evaluate, cursor visibility rules, screenshots, navigation events, the
popup, reconnection after a hub restart, and an extension reload (orphaned content scripts are
replaced by injection). Set `AIM_E2E_HEADED=1` to watch it. Headless Chromium reports every tab as
visible, so the "cursor hidden in background tabs" rule is exercised only in a headed browser.

## Hub-side expectations

Beyond `@aim/shared/extension.ts`:
- The hub must answer `hub.hello` with an `RpcSuccess` (`{ ok: true, hubVersion, serverTime }`) and
  close with code `4001` on a bad token.
- The hub should answer `hub.ping` requests from the extension (any `RpcSuccess`, or even an
  `RpcFailure` such as MethodNotFound counts as alive); two unanswered pings in a row make the
  extension reconnect.
- `ext.tabs.create` defaults to `active: false` and the last focused normal window; it never creates
  a window. If no normal window exists it returns `ToolFailed` with a message saying so.
- `ext.tabs.navigate` accepts `"back"`, `"forward"` and `"reload"` as `url`. On load timeout (30 s)
  it returns `Timeout` with `data.tab` so the hub can still continue. Chromium skips history entries
  created without user activation (every A.I.M.-driven navigation), so when the browser refuses to
  go back/forward the extension falls back to its own per-tab URL record and navigates explicitly.
- `ext.page.screenshot` fails with `ToolFailed` for background tabs; `ext.page.evaluate` fails with
  `ToolFailed` when the page's CSP forbids `eval`.
- Policy refusals use `RpcErrorCode.PolicyBlocked` with `PAYMENT_BLOCK_MESSAGE` and are mirrored as
  `ext.event` `policy.blocked`.
